# 简历素材（RepoPilot）

> 用法：A/B 二选一。所有数字均为单次采样，简历上保留分母和口径。

## 版本 A：Agent 应用开发岗

**RepoPilot｜给 Python 仓库注入失败单测，agent 自己定位、改码、跑测试**
Python 3.14 / OpenAI SDK / Docker / pytest

- **主干**：三层题集——自造基础 10 题 10/10、自造跨文件 3 题 1/3、真实仓库 1 题 0/1；基础题平均 3.2 轮、单题 3,491 token、¥0.0025，均为单次采样。
- **失败恢复**：真实仓库题出现假阳性——harness 判通过，人工复核发现源码和测试都没改；根因是 `pytest ... | tail` 把退出码换成 0。加 shell 元字符拦截 + 题目原命令无条件复跑后，复跑为 0/1。
- **评测体系**：题集分三层，mock/real 两条执行路径；每题落 JSONL trace（工具、耗时、token、熔断标记），报告按题、轮数、token、成本、失败原因出表，失败分模型/工具/预算/上下文四类。

**❌ / ✅ 对照**

- ❌ "13 题过 12 题，通过率 92%，模型效果很好。"——单次、无分母、无沙箱。
- ✅ "容器单次 12/13（92.3%），同模型本机 11/13；差 1 题按采样噪声记录，不下因果结论。"

## 版本 B：AI 测开 / 评测岗

**RepoPilot｜给 Python 仓库注入失败单测，agent 自己定位、改码、跑测试**
Python 3.14 / OpenAI SDK / Docker / pytest

- **评测集构造**：自造 13 题覆盖 5 类注入 bug；真实题以 cachetools HEAD `e7104dd` 为底，反向应用 bugfix `2609f06` 的非测试源码 hunk，测试保留 HEAD 回归测试；初始 18 failed / 369 passed，正向应用同一 patch 后 381 passed。
- **复核闸口**：模型命令 exit 0 不算通过，必须用题目原始 test_cmd 再跑一遍；假阳性从判 True 改为 `false_positive_blocked`，真实题复跑 0/1。
- **失败归因**：按模型/工具/预算/上下文四类落到 trace；真实题 12 步 10 次读、0 次写判模型主因，报错文案与实现不一致判工具放大。

**❌ / ✅ 对照**

- ❌ "真实仓库也跑通了。"——只报了首轮 harness 判定。
- ✅ "首轮判 True，人工复核 18 failed 未变，改判假阳性；加固后复跑 0/1。证据在 `eval/reports/w3-real.md`。"

## 面试前必做

把每个数字对到 `eval/reports/` 的具体文件；下面 4 个数字必须能当场说出分母。

| 数字 | 出处 | 你必须能回答 |
|---|---|---|
| 基础 10/10，3.2 轮，3,491 token/题，¥0.0025 | `w2-summary-cost.md` | 题是不是自己出的？单文件还是跨文件？单价怎么来的？ |
| 跨文件 1/3，20,681 token/题 | `w3-hard.md` | 失败的 2 题是 `max_steps` 还是判错？8 步预算是否太紧？ |
| 真实仓库 0/1，12 步，prompt 123,088 | `w3-real-2.md` | 是模型没改，还是工具/预算卡住？为什么是 0/1 不是 1/1？ |
| 容器 12/13（92.3%） | `w2-summary-docker.md` | 分母多少？跑了几次？本机为什么是 11/13？ |

另外两个数字也要背：假阳性首轮 True → 复核 False（`w3-real.md`）；熔断 prompt 31,709 → 21,283（−33%，`w2-breaker.md`），通过率不变。

口径问题清单：① 每次都说"单次采样"；② 每次都给分母和沙箱；③ 成本说"按 .env 单价算，单价待校准"；④ 失败题不拿"省了 token"当成功。
