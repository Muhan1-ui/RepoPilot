**熔断单独的效果（A→B）。** 两组的步数上限都是 8，唯一变量是熔断，因此 A→B 可以干净地归因于熔断本身。prompt token 从 31,709 降到 21,283（−10,426，约 −33%），单题成本从 ¥0.0529 降到 ¥0.0248（−53.1%），ERROR 步数从 6 降到 4。但通过率没有任何变化：A、B 都是 False。也就是说熔断的作用是"更早止损、少烧 token"，它没有把失败变成成功，省钱和省 token 是建立在"这题本来就没做出来"的前提上的。

**步数预算单独的效果（B→C）。** C 相对 B 同时改了两件事：步数上限 8→12，以及路径归一化，因此这一次无法把"步数预算"和"路径修复"的贡献完全分离。可以看到的是：C 通过了，但实际只用了 8 步（没有触到 12 步上限），prompt token 反而从 21,283 升到 26,484（+24.4%），成本从 ¥0.0248 升到 ¥0.0383（+54.4%），ERROR 从 4 降到 3（trace 中仍保留 1 个 step 2 的 path 类 ERROR）。由于 C 的步数没有超过 8，把通过归因于"预算放宽到 12"缺乏证据；更可能是路径修复减少了无效往返，从而在 8 步内完成任务。要真正分离两者，做法是：固定 8 步上限、保留熔断、只加路径归一化再跑一次——若此时能通过，则说明起作用的是路径修复而非步数预算；若仍失败，才说明 12 步预算本身是必要的。

**成本口径。** 按"每个修好的题的成本"算，A 和 B 都没修好，成本是 ∞（花了钱但产出为零），C 是 ¥0.0383；按"每题成本"算，C 也是 ¥0.0383。A→B 表面上成本/ token 降了约 33%，但这一降幅只发生在两题都失败的场景里，是把"失败的探索"变短了，而不是把"成功的解题"变便宜了。所以"成本降 33%"只能在失败题的口径下陈述，不能拿来宣称优化成功；真正的成本改善指标应当是"每个修复成功的题的成本"。

支持：熔断能在失败样本上压低无效探索的 token 与成本（A→B 约 −33% token），这一点可以下结论。不支持：不能据此宣称整体优化成功——通过率没有提升，C 的通过是 12 步预算与路径修复共同作用、且尚未与熔断分离的结果，不能写成"熔断带来的提升"。
