# W2：本机 subprocess vs docker（--network=none）对照

同一 13 题集（bug_0001–bug_0013）、同一模型 `deepseek-flash`、`max_steps=8`。

- 容器侧：`eval/reports/w2-summary-docker.json`（run `20261031-002141`，13 题一次跑完）
- 本机侧：`w2-summary-cost`（bug_0001–0010，run `20261031-000620`）+ `w3-hard`（bug_0011–0013，run `20261031-001241`）合并，均为 `--no-docker`、`max_steps=8`；平均轮数/总 token/成本/耗时按 13 题重新汇总
- 镜像 `repopilot-sandbox:pytest9`，容器内 Python 3.12.16；本机 Python 3.14.9

| 项 | 本机 subprocess | docker --network=none |
|---|---|---|
| 通过数 | 11/13（84.6%） | 12/13（92.3%） |
| 平均轮数 | 3.36（通过题）/ 4.08（全部） | 3.67（通过题）/ 4.00（全部） |
| 总 token | 96,953（prompt 85,348 / completion 11,605） | 96,690（prompt 86,194 / completion 10,496） |
| 总成本 | ¥0.0963 | ¥0.0874 |
| 总耗时 / 单题平均耗时 | 111.94s / 8.61s | 114.82s / 8.83s |

说明：

1. **容器慢在每次测试命令的进程启动**：单次 `docker run --rm` 空跑中位数约 0.60s，本机 python 启动约 0.06s，即每条 pytest 命令多 ~0.55s；本次 13 题共 52 步，累计开销被模型 API 延迟摊薄，总耗时只多了 2.9s（+2.6%），单题差异在模型响应抖动范围内。
2. **通过率不一致，且只差一题**：bug_0013 本机 `ok=False`（8 步，`max_steps`），容器内 `ok=True`（7 步，`tests_passed`）。本机 trace：`eval/bugsets/bug_0013/runs/20261031-001241/trace.jsonl`；容器 trace：`eval/bugsets/bug_0013/runs/20261031-002141/trace.jsonl`。bug_0012 两边都不通过（均为 `max_steps`，8 步），其余 11 题两边一致通过。
3. **成本不完全一致但同量级**：总 token 只差 0.3%，成本差约 9%，主要来自 completion token（11,605 vs 10,496），大头是 bug_0012 单题 6,454 vs 4,912 —— 同一模型两次采样的输出长度不同，不是沙箱造成的固定偏差。
4. **解释器差异注脚（原结论，保留作历史记录）**：

   > 容器内是 Python 3.12.16，本机是 3.14.9；两边通过率若不同，应先怀疑解释器/依赖版本差异，再怀疑模型行为差异（本次唯一差异题 bug_0013 需要结合两份 trace 才能定因）。

   **修正**：上面这条的方法论顺序是错的。模型是随机采样的，单次运行差 1 题几乎必然是采样噪声（同一臂两次跑也会差 1 题）。解释器差异（容器 Python 3.12.16 vs 本机 3.14.9）只是次要假设。要区分二者，必须每臂各跑 ≥2 次取交集；当前数据只有单次，因此**不下结论**，只记录差异。
